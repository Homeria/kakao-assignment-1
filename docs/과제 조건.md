# React로 Todo 앱 만들기

## 한 줄 소개

Vanilla JS로 제작한 Todo 앱을 React Function Component 구조로 변환하는 과제입니다.

## 최종 프로젝트

https://github.com/elice-ai-training/kakaotech.campus_assignment2

## 과제 목표

- 컴포넌트 단위로 UI를 분리하고, props와 state의 역할 이해하기
- AI를 활용해 마이그레이션하고, 생성된 코드를 직접 읽고 수정하기
- 에러 메시지를 AI와 함께 분석하고 해결하는 디버깅 흐름 익히기
- Vanilla JS와 React 개발 방식의 차이 이해하기

### 1. 프로젝트 세팅하기

Vite를 사용해 React 프로젝트를 구성하고, `localhost:5173`에 접속하여 화면을 확인한다.

```bash
npm create vite@latest . -- --template react
npm install
npm install -D tailwindcss @tailwindcss/vite
npm run dev
```

`vite.config.js`

```js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [
    tailwindcss(),
    react(),
  ],
});
```

`src/index.css`

```css
@import "tailwindcss";
```

### 2. Todo CRUD 기능 마이그레이션하기

- 텍스트 입력창과 추가 버튼으로 새로운 Todo를 생성할 수 있어야 한다.
- 입력값이 비어있는 경우 Todo가 생성되지 않고 사용자에게 안내 메시지를 표시해야 한다.
- 생성된 Todo는 목록 형태로 화면에 표시되어야 한다.
- 각 Todo 항목은 수정 / 완료 처리 / 삭제가 가능해야 한다.
- 완료 처리된 Todo는 시각적으로 구분되어야 한다. 예: 텍스트 취소선
- `prompt()` 대신 인라인 입력창으로 수정 UI를 구현해야 한다.

확인 포인트:

- `isEditing` 같은 수정 상태가 바뀌면 화면이 어떻게 달라지는가?
- `useState`가 어디에 선언되어 있고 어떤 값을 관리하는가?

### 3. 상태별 필터링 기능 마이그레이션하기

- 전체 / 진행 중 / 완료 필터 탭을 통해 원하는 Todo만 볼 수 있어야 한다.
- 현재 선택된 필터 탭은 시각적으로 구분되어야 한다.
- 필터 상태는 `useState`로 관리한다.
- 탭 전환 후 새 Todo를 추가해도 필터가 유지되어야 한다.

확인 포인트:

- 탭 전환 후 새 Todo를 추가했을 때도 필터가 유지되는가?
- 필터 상태가 바뀌면 TodoList가 어떻게 다시 그려지는가?

### 4. Todo 일간 뷰 마이그레이션하기

- 화면에 오늘 날짜가 표시되어야 한다.
- 이전 / 다음 날짜로 이동할 수 있어야 한다.
- 선택된 날짜에 해당하는 Todo만 표시되어야 한다.
- Todo를 생성하면 현재 선택된 날짜가 자동으로 저장되어야 한다.
- 선택된 날짜 상태는 `useState`로 관리한다.

확인 포인트:

- 날짜를 이동했을 때 해당 날짜의 Todo만 표시되는가?
- 다른 날짜에 Todo를 추가한 뒤 날짜를 이동해도 각각 따로 관리되는가?
- Todo에 날짜가 어떤 형태로 저장되는가?

### 5. 로컬 스토리지 연동 마이그레이션하기

- Todo의 변경사항은 항상 localStorage에 저장되어야 한다.
- 새로고침 후에도 기존 데이터가 유지되어야 한다.
- 데이터는 JSON 형태로 저장하고 불러와야 한다.
- `JSON.stringify` / `JSON.parse`를 사용한다.
- `useEffect`를 활용해 todos 변경 시 자동으로 저장한다.

확인 포인트:

- Todo를 추가한 뒤 새로고침해도 데이터가 유지되는가?
- 브라우저 개발자 도구의 Application -> Local Storage에서 데이터가 실제로 저장되어 있는가?
- `useEffect`의 의존성 배열에 무엇이 들어가는가?

예시:

```jsx
const [todos, setTodos] = useState(() => {
  const saved = localStorage.getItem("todos");
  return saved ? JSON.parse(saved) : [];
});

useEffect(() => {
  localStorage.setItem("todos", JSON.stringify(todos));
}, [todos]);
```

## React에서 자주 발생하는 에러

### Tailwind 라이브러리가 적용되지 않는 경우

Tailwind가 설치되지 않았거나 Vite 설정에 Tailwind 플러그인이 빠졌을 수 있다.

```bash
npm install -D tailwindcss @tailwindcss/vite
```

### Each child in a list should have a unique "key" prop

`map()`으로 리스트를 렌더링할 때 각 항목에 고유한 `key` prop이 없으면 발생한다.

```jsx
{todos.map(todo => (
  <TodoItem key={todo.id} todo={todo} />
))}
```

### Too many re-renders

이벤트 핸들러에 함수를 즉시 호출하면 렌더링 중 상태가 변경되어 무한 루프가 발생한다.

```jsx
// 잘못된 방법
<button onClick={handleDelete(todo.id)}>삭제</button>

// 올바른 방법
<button onClick={() => handleDelete(todo.id)}>삭제</button>
```

### 새로고침하면 데이터가 사라지는 경우

초기값을 localStorage에서 불러오지 않았거나, `useEffect` 의존성 배열이 잘못되었을 수 있다.

### Cannot read properties of undefined

props로 전달받은 값이 `undefined`인 상태에서 `map()` 등을 호출할 때 발생한다.

```jsx
function TodoList({ todos = [] }) {
  return todos.map(todo => <TodoItem key={todo.id} todo={todo} />);
}
```
