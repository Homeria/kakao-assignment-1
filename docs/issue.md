## AI 활용 내역

### 1. 전체 틀 잡기
- 직접 진행한 것
    - 기본 조건에 대하여 서술하기
        - HTML / CSS / Vanilla JS만을 이용.
        - Library, Framework 사용 금지.
        - Main Color로 #672be0 사용.
        - 기타 코드의 가독성을 위한 조건(예: 변수명과 함수명은 역할을 알 수 있도록 명확하게 작성, 주석 등)
        - 모든 작업을 마친 후에는 구현 기능을 체크리스트로 답변
    - 작업에 대한 순서와 그 작업에 대하여 자세한 조건 서술하기 - docs/requirements/0. total structure.md 참고
        - Todo CRUD(Create, Read, Update, Delete) 구현
            - 예시 : 텍스트 입력창과 추가 버튼으로 Todo를 생성할 수 있어야 함.
        - 상태별 필터링 구현
            - 예시 : 전체 / 진행 중 / 완료 필터 탭을 통해 원하는 Todo만 볼 수 있어야 함.
    - AI 활용을 통한 work plan의 work 단위 수동 설정과 아키텍처의 추가 설명
        - 하나의 branch에서 진행해야 하므로, commit이 중요하다고 판단하여 commit 단위의 work를 계획해달라고 서술
        - html, css, js 각각 한 개의 파일에 코드를 담기에는 방대해질 것으로 생각하여, 컴포넌트 단위로 개발할 것을 지시
        - layered architecture까지 고려했으나 오버엔지니어링같다는 생각에 AI도 동의했으므로 엄격한 단위로 분리하진 않음
- 직접 수정한 부분
    - 아키텍처와 작동 방식에 대하여 AI의 계획을 들어보고, 너무 추상적이거나 적절하지 않아 보이는 계획들은 철회를 명령
    - 어떤 부분에서 부적절한지를 요구사항 내지 work plan의 내용을 직접 수정
- AI 활용 내용
    - work plan 제작
        - 가독성과 유지보수성을 위한 아키텍처 모듈(컴포넌트) 분리 계획과 파일 구조를 결정
        - 적절한 commit 단위의 work 결정
    - 기본 작동 원리 기준 확립
        - 기본 index.html 내의 body에는 특별한 tag들이 없고, js의 상호작용을 통해 즉각적으로 이벤트 리스너(핸들러)로 처리하도록 기준을 확립
    - UI의 기본 구조 결정
        - 요구사항 명세를 확인하여 필요한 기능들을 작업 전에 결정

### 2. 전반적인 코딩과 테스트 케이스
- 직접 진행한 것
    - 디자인 관련 피드백
        - UI가 적절하지 않은 경우에 대하여 어떠한 문제가 발생했는지를 자세히 서술하고 이를 통해 UI/UX 고도화
    - HTML-JS의 상호작용 파악
        - AI가 전반적인 코딩을 담당했으나 생각보다 버그가 없어 막힘 없이 구현
        - Commit 단위로 초기 계획에 따라 잘 구현되고 있는지를 코드 점검 및 테스트 진행
        - AI가 작성해준 주석이 잘 작성됐는지를 전반적인 코드 점검을 하며 점검
    - 테스트 진행
        - Chrome MCP를 통하여 테스트를 맡겨볼 수도 있었으나, 테스트 케이스에 따라 직접 테스트를 진행
        - 사람이 직접 테스트해봐야 보이는 문제가 있으므로 수동 체크
        - 테스트를 직접 진행하며 Todo 주간 UI의 좌우 이동 버튼 추가 아이디어를 도출하고 이를 서술하여 AI가 구현
- 직접 수정한 부분
    - index.html의 메인 로고명 변경
        - 초기 로고명은 TaskFlow였으나, Flow라는 단어가 개인적으로 '흐름'을 나타내는 듯 하여 평범하게 TodoList로 변경
- AI 활용 내용
    - 전반적인 코딩
        - 비교적 명확하고 분명한 명세에 따라 Commit 단위로 개발을 진행
        - 명세와 아키텍처가 명확하여 생각보다 버그를 최소한으로 하여 개발
        - LocalStorage를 통한 Data I/O, 코드 로직 등 전반적인 코드 구조에서 에러가 발생하지 않았음을 확인
    - Todo 주간 UI의 좌우 이동 버튼 추가
        - 원래는 일 단위로 이동이 가능하도록 구현했으나, 일->월, 월->일 부분에서의 사용자 경험이 좋지 않다고 테스트를 통해 판단
        - 일주일 단위로 이동이 가능한 버튼을 명령하여 추가
    - 문서 고도화
        - 아키텍처를 주의깊게 보라는 초기 명령에 따라 아키텍처에 대한 문서를 남김
        - 문서 안에는 Mermaid 다이어그램을 작성하여 Github에서 해당 문서를 볼 때 그래프가 정상적으로 렌더링
    - 주석 작성
        - 코드와 아키텍처를 명확하게 파악할 수 있게 해달라는 초기 명령에 따라 주석을 알기 쉽게 작성
        - HTML-JS 상호작용 파악과 코드 점검에 큰 도움이 됨
    - 테스트 케이스 작성
        - 다양한 테스트 케이스를 구성하여 문서로 남기고, 사용자가 점검할 수 있도록 체크 박스 제작
        - 테스트는 수동으로 진행했음
