# Next.js Todo 앱 작업 계획

## 1. 작업 방향

이번 과제는 2차 과제에서 만든 React(Vite) Todo 앱을 Next.js App Router와 FastAPI 기반 풀스택 구조로 전환하는 작업이다. 단순히 3차 과제 샘플을 복제하기보다, 2차 결과물에서 구현한 날짜 기반 Todo 경험과 컴포넌트 분리 방식을 유지하면서 저장소와 데이터 흐름을 서버 중심으로 바꾼다.

2차 과제의 핵심은 `Component + Hook + Service + Repository` 구조였다. 3차 과제에서는 localStorage Repository가 FastAPI와 SQLite로 대체된다. 프론트엔드에서는 서버에서 받은 데이터를 렌더링하고 사용자 입력을 API 요청으로 전달한다. 백엔드에서는 Todo 데이터의 영속성, 필터링, 검색을 담당한다.

이번 작업에서 각 계층의 책임은 다음처럼 나눈다.

- Next.js Page: URL 경로와 페이지 단위 데이터 조회
- Server Component: 서버에서 가능한 데이터 조회와 정적 UI 렌더링
- Client Component: 입력, 클릭, 검색, 날짜 이동 등 사용자 인터랙션 처리
- API Route: 클라이언트 요청을 FastAPI로 전달하는 프록시
- Server Actions 또는 서버 함수: 서버에서 FastAPI를 호출하는 데이터 접근 함수
- FastAPI: Todo CRUD, 필터링, 검색, DB 세션 처리
- SQLite: Todo 데이터 영속 저장
- Utils: 날짜 계산과 URL 파라미터 처리 같은 순수 로직

## 2. 기술 스택 및 기본 조건

- Frontend: Next.js, React, TypeScript, Tailwind CSS
- Backend: FastAPI, Uvicorn, SQLAlchemy, Pydantic, SQLite
- 라우팅: Next.js App Router
- 데이터 저장: localStorage가 아닌 SQLite
- API 통신: Next.js API Route와 FastAPI 연동
- 설정값 관리: `.env.local`
- 제출 문서: 과제 조건, 작업 계획, 검증 결과, 보고서 작성

## 5. 데이터 모델 설계

2차 과제에서는 날짜별 객체 안에 Todo 배열을 저장했다.

```js
{
  "2026-06-22": [
    {
      "id": 1719000000000,
      "text": "Todo 작성",
      "completed": false
    }
  ]
}
```

3차 과제에서는 DB 테이블의 각 row가 하나의 Todo를 나타내도록 평탄화한다.

```text
todos
  id: integer primary key
  title: string
  completed: boolean
  date: string
  created_at: datetime
  updated_at: datetime
```

2차의 `text`는 백엔드와 API에서는 `title`로 사용한다. 화면에서는 사용자가 보는 문구가 더 자연스럽도록 "할 일" 또는 "Todo 내용"으로 표현한다.

## 6. URL 상태 설계

3차 과제에서는 새로고침과 공유 가능한 상태를 위해 주요 UI 상태를 URL 쿼리로 관리한다.

```text
/todos?date=2026-06-22
/todos?date=2026-06-22&filter=active
/todos?date=2026-06-22&filter=completed&search=회의
```

쿼리 파라미터:

- `date`: 선택 날짜
- `filter`: `all`, `active`, `completed`
- `search`: 검색어
- `weekStart`: 주간 뷰 기준 날짜

서버에 전달할 조건:

- `date`
- `filter`
- `search`

프론트에서만 사용할 수 있는 조건:

- `weekStart`: 주간 UI 표시 기준

단, 주간 날짜별 Todo 개수를 서버에서 조회하도록 확장할 경우 `weekStart`도 FastAPI로 전달한다.

## 7. 데이터 흐름

### 목록 조회

```text
사용자 /todos 접속
  -> page.tsx가 searchParams 파싱
  -> actions.ts 또는 서버 fetch로 FastAPI 조회
  -> FastAPI가 SQLite에서 조건에 맞는 Todo 조회
  -> Server Component가 초기 화면 렌더링
  -> Client Component가 인터랙션 담당
```

### Todo 생성

```text
사용자 입력
  -> TodoForm Client Component
  -> /api/todos POST
  -> route.ts
  -> FastAPI POST /todos
  -> SQLite 저장
  -> router.refresh() 또는 페이지 이동
  -> 목록 재조회
```

### Todo 수정

```text
수정 페이지 접근
  -> page.tsx에서 Todo 상세 조회
  -> 수정 Form 렌더링
  -> /api/todos/{id} PUT
  -> FastAPI PUT /todos/{id}
  -> SQLite 업데이트
  -> 목록 페이지 이동 또는 refresh
```

### Todo 삭제

```text
삭제 버튼 클릭
  -> /api/todos/{id} DELETE
  -> route.ts
  -> FastAPI DELETE /todos/{id}
  -> SQLite 삭제
  -> router.refresh()
```

### 필터와 검색

```text
필터 클릭 또는 검색어 입력
  -> URL 쿼리 변경
  -> /api/todos?filter=active&search=...
  -> route.ts
  -> FastAPI /todos?filter=active&search=...
  -> DB에서 서버 기반 필터링
  -> 결과 렌더링
```

- 오늘 날짜와 선택 날짜 스타일 구분
- 해당 날짜의 Todo 개수 표시
- 클릭 시 URL의 `date`와 `weekStart` 변경 요청

### DateHeader

- 선택 날짜를 한국어 형식으로 표시

- 날짜 이동 시 URL 쿼리 변경

### FilterTabs

- 전체 / 진행 중 / 완료 탭 표시
- 선택된 필터를 시각적으로 구분
- 클릭 시 URL의 `filter` 변경
- 검색어와 날짜 쿼리는 유지

### TodoSearch

- 검색어 입력 UI 제공
- 입력값은 즉시 로컬 state에 반영
- 일정 시간 디바운스 후 URL의 `search` 변경
- 검색어 삭제 시 `search` 파라미터 제거

- 완료 상태 스타일 표시

- 삭제 버튼
- 직접 DB를 수정하지 않고 API Route를 호출

### TodoForm

- 생성 페이지와 수정 페이지에서 재사용 가능하도록 구성

- 완료 상태 수정
- 빈 값 제출 방어
- 저장 중 상태 표시

### EmptyState

- 현재 조건에 맞는 Todo가 없을 때 표시
- 검색어가 있는 경우와 단순 빈 목록인 경우 메시지 구분

## 10. Server Component와 Client Component 구분

### Server Component로 유지할 영역

- `app/layout.tsx`
- `app/page.tsx`
- `app/todos/page.tsx`의 초기 데이터 조회 영역
- `app/todos/[todoId]/page.tsx`의 상세 데이터 조회 영역
- 정적인 제목, 레이아웃, 설명 영역

### Client Component로 분리할 영역

- 검색 입력
- 필터 탭 클릭
- 날짜 이동 버튼
- 주간 날짜 카드 클릭
- Todo 생성 Form
- Todo 수정 Form
- 완료 토글 버튼
- 삭제 버튼

기준:

- `useState`, `useEffect`, `useRouter`, `useSearchParams`, `onClick`, `onChange`가 필요하면 Client Component로 분리한다.
- 데이터 조회만 필요하면 Server Component에서 처리한다.

## 11. API 설계 상세

### FastAPI

```text
GET    /todos
POST   /todos
GET    /todos/{todo_id}
PUT    /todos/{todo_id}
DELETE /todos/{todo_id}
```

`GET /todos` 쿼리 파라미터:

- `date`
- `filter`
- `search`

응답 예시:

```json
[
  {
    "id": 1,
    "title": "Next.js 과제 진행",
    "completed": false,
    "date": "2026-06-22",
    "created_at": "2026-06-22T10:00:00",
    "updated_at": "2026-06-22T10:00:00"
  }
]
```

### Next.js API Route

```text
GET    /api/todos
POST   /api/todos
GET    /api/todos/{todoId}
PUT    /api/todos/{todoId}
DELETE /api/todos/{todoId}
```

API Route는 요청을 변형하지 않고 FastAPI로 전달하는 것을 기본으로 한다. 다만 환경변수 보호, CORS 회피, 공통 에러 처리를 담당한다.

## 13. 구현 시 주의할 점

- 모든 컴포넌트에 `"use client"`를 붙이지 않는다.
- Server Component에서 이벤트 핸들러를 사용하지 않는다.
- 클라이언트 컴포넌트에서 `BACKEND_URL`을 직접 사용하지 않는다.
- 클라이언트 요청은 `NEXT_PUBLIC_API_URL` 또는 상대 경로 `/api`를 사용한다.
- FastAPI URL은 서버 전용 환경변수인 `BACKEND_URL`로 관리한다.
- `.env.local`은 Git에 포함하지 않는다.
- API Route에서 FastAPI 응답 실패를 그대로 성공 응답처럼 반환하지 않는다.
- 빈 제목은 프론트와 백엔드 양쪽에서 방어한다.
- 날짜 문자열은 `YYYY-MM-DD`로 통일한다.
- 검색어와 필터는 클라이언트에서만 필터링하지 않고 서버로 전달한다.
- 2차에서 좋았던 컴포넌트 분리와 책임 분리를 유지한다.
- 샘플 코드처럼 하나의 Client Component에 모든 로직이 몰리지 않게 한다.
