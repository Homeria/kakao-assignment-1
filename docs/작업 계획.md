# React Todo 앱 마이그레이션 작업 계획

## 1. 작업 방향

이번 과제는 `vanilla_js_version`에 구현된 Todo 앱을 React Function Component 기반 프로젝트로 마이그레이션하는 작업이다. 과제 제출 단위가 별도 저장소가 아니라 브랜치 기준이므로, 새 브랜치를 여러 개 파서 기능을 나누기보다 하나의 작업 흐름 안에서 커밋 단위로 진행한다.

작업은 기능 단위가 아니라 컴포넌트 단위와 상태 계층 단위를 함께 기준으로 나눈다. React에서는 DOM을 직접 조작하지 않고 상태가 UI를 다시 그리도록 만드는 것이 핵심이다. 기존 Vanilla JS의 `Store + Observable + Component` 구조를 그대로 복제하지 않고, React에 맞게 `Component + Hook + Service + Repository` 구조로 재구성한다.

이번 마이그레이션에서 각 계층의 책임은 명확히 분리한다.

- Component: 화면 표시와 사용자 이벤트 전달
- Hook: React state와 외부 저장소 동기화
- Service: Todo 도메인 규칙과 데이터 변환
- Repository: localStorage 입출력과 직렬화 처리
- Utils: 날짜 계산처럼 특정 도메인에 종속되지 않는 순수 유틸리티

## 2. 기술 스택 및 기본 조건

- React 18 이상
- Vite 5.x 기반 React 프로젝트
- Tailwind CSS v4
- JavaScript
- Web Storage API (`localStorage`)
- Todo 데이터는 JSON 형태로 저장 및 복구
- `prompt()`를 사용하지 않고 인라인 수정 UI로 구현
- 메인 컬러는 기존 과제와 동일하게 `#672be0` 유지

## 4. React 컴포넌트 계층 설계

컴포넌트는 화면 역할과 상태 소유 범위를 기준으로 나눈다. 최상위 `App` 컴포넌트가 주요 상태와 액션을 소유하고, 하위 컴포넌트는 props로 필요한 값과 이벤트 핸들러만 전달받는다.

```text
src/
  App.jsx
  main.jsx
  index.css
  components/
    debug/
      DebugPanel.jsx
    date/
      DateHeader.jsx
      WeeklyView.jsx
      WeeklyDayCard.jsx
    filter/
      FilterTabs.jsx
    todo/
      TodoInput.jsx
      TodoList.jsx
      TodoItem.jsx
      EmptyState.jsx
  hooks/
    useStoredState.js
  services/
    todoService.js
  repositories/
    todoStorageRepository.js
    uiStorageRepository.js
  utils/
    date.js
  constants/
    filters.js
    storage.js
```

### 계층별 책임

`App.jsx`

- 전체 애플리케이션 상태 소유
- `todos`, `selectedDate`, `activeFilter`, `weekStartDate` 관리
- Todo Service를 호출하여 다음 상태 계산
- 날짜 이동, 필터 변경, 주간 이동 액션 조립
- Hook을 통해 Repository와 상태 동기화
- 하위 컴포넌트에 상태와 이벤트 핸들러를 props로 전달

`components/`

- UI 표현과 사용자 입력 이벤트 처리
- 직접 localStorage에 접근하지 않음
- 직접 날짜 계산을 복잡하게 수행하지 않음
- Todo 데이터를 직접 변경하지 않음
- 상위에서 받은 props와 콜백으로만 동작

`hooks/useStoredState.js`

- Repository의 `load` / `save` 함수를 React state와 연결
- 초기값 로드는 함수형 초기화로 한 번만 수행
- 상태 변경 시 Repository를 통해 저장
- 저장소가 localStorage인지 여부를 직접 알지 않음

`repositories/todoStorageRepository.js`

- Todo 데이터 저장/조회 전담
- `taskflow_todos_data` key 사용
- localStorage 입출력 처리
- JSON 직렬화 / 역직렬화 처리
- 저장소 접근 실패 시 안전한 기본값 반환

`repositories/uiStorageRepository.js`

- Todo 내용이 아닌 UI 상태 저장/조회 전담
- 주간 뷰 기준 날짜 등 화면 상태를 저장
- 추후 선택 날짜나 필터 상태 저장이 필요해질 경우 이 계층에 확장

`utils/date.js`

- `YYYY-MM-DD` 변환
- 로컬 타임존 기준 날짜 파싱
- 일 단위 이동
- 주 시작일 계산
- 주간 날짜 목록 생성
- 한국어 날짜 포맷

`services/todoService.js`

- 선택 날짜의 Todo 조회
- 필터 조건 적용
- 날짜별 Todo 개수 계산
- Todo 추가, 수정, 삭제, 완료 토글에 필요한 순수 데이터 변환
- 빈 날짜 key 삭제 같은 Todo 도메인 규칙 처리
- React state나 localStorage에 직접 접근하지 않음

`constants/`

- 필터 값
- localStorage key
- 화면에서 반복 사용하는 고정 문자열 관리

## 5. 상태 설계

React 상태는 지나치게 중첩하지 않고, Todo 데이터와 UI 상태를 분리한다.

```js
const [todosByDate, setTodosByDate] = useStoredState(
  todoStorageRepository.load,
  todoStorageRepository.save
);
const [selectedDate, setSelectedDate] = useState(getTodayDateKey());
const [activeFilter, setActiveFilter] = useState('all');
const [weekStartDate, setWeekStartDate] = useStoredState(
  () => uiStorageRepository.loadWeekStartDate(getWeekStartDate(getTodayDateKey())),
  uiStorageRepository.saveWeekStartDate
);
```

Todo 데이터 구조는 기존 Vanilla JS 버전과 호환되도록 유지한다.

```js
{
  '2026-06-09': [
    {
      id: 1717900000000,
      text: 'React Todo 구현하기',
      completed: false
    }
  ]
}
```

이 구조를 유지하면 기존 Vanilla JS 앱에서 만든 localStorage 데이터와도 마이그레이션 비용이 낮다.

## 6. 데이터 흐름

React 앱은 단방향 데이터 흐름을 따른다.

```text
사용자 입력
  -> 하위 컴포넌트 이벤트 발생
  -> App의 액션 함수 호출
  -> todoService로 다음 상태 계산
  -> setState로 React 상태 업데이트
  -> 필요한 파생 데이터 계산
  -> props로 하위 컴포넌트 재전달
  -> 화면 자동 갱신
  -> useStoredState가 Repository를 통해 localStorage 저장
```

Vanilla JS 버전에서는 `store.publish()`로 컴포넌트 재렌더링을 직접 알렸지만, React 버전에서는 `setState` 호출 자체가 화면 갱신의 출발점이 된다.

Repository는 localStorage의 현재 값을 직접 변경하는 CRUD 계층이 아니라, 저장소 입출력을 캡슐화하는 계층으로 둔다. Todo 생성, 수정, 삭제 같은 도메인 규칙은 `todoService.js`의 순수 함수에서 처리하고, React state가 변경되면 Hook이 Repository를 통해 저장한다. 이렇게 하면 React state와 localStorage가 이중 원본이 되는 문제를 피할 수 있다.

- `onAddTodo`

를 props로 받는다.

입력값은 컴포넌트 내부 state로 관리한다. 빈 값 제출 시 Todo를 추가하지 않고 안내 메시지를 표시한다.

### FilterTabs

- `activeFilter`
- `onChangeFilter`

를 props로 받는다.

필터 값은 상위 상태에 있고, 탭 컴포넌트는 현재 필터와 변경 이벤트만 담당한다.

### TodoList

- `todos`
- `onToggleTodo`
- `onUpdateTodo`
- `onDeleteTodo`

를 props로 받는다.

리스트가 비어 있으면 `EmptyState`를 보여준다. 리스트 항목 렌더링은 `TodoItem`에 위임한다.

### TodoItem

- 개별 Todo의 표시
- 완료 토글
- 삭제
- 인라인 수정 모드
- 저장 / 취소 / Enter / Escape 처리

수정 중인 입력값과 수정 모드 여부는 `TodoItem` 내부 state로 관리한다. 실제 Todo 데이터 변경은 저장 시 상위 콜백으로 요청한다.

## 9. 검증 체크리스트

### Todo CRUD

- [ ] 빈 값으로 추가 시 안내 메시지가 표시된다.
- [ ] Todo를 추가하면 현재 날짜 목록에 표시된다.
- [ ] Todo 완료 버튼을 누르면 완료 상태와 스타일이 바뀐다.
- [ ] Todo 수정 버튼을 누르면 인라인 입력창으로 전환된다.
- [ ] 수정 저장 시 텍스트가 변경된다.
- [ ] 수정 취소 시 기존 텍스트가 유지된다.
- [ ] Todo 삭제 시 목록에서 제거된다.

### 필터

- [ ] 전체 탭에서 모든 Todo가 보인다.
- [ ] 진행 중 탭에서 미완료 Todo만 보인다.
- [ ] 완료 탭에서 완료 Todo만 보인다.
- [ ] 현재 선택된 탭이 시각적으로 구분된다.
- [ ] 필터 선택 후 Todo를 추가해도 필터가 유지된다.

### 일간 뷰

- [ ] 오늘 날짜가 표시된다.
- [ ] 이전 날짜로 이동할 수 있다.
- [ ] 다음 날짜로 이동할 수 있다.
- [ ] 날짜별 Todo가 분리되어 표시된다.
- [ ] Todo 추가 시 현재 선택 날짜에 저장된다.

### 주간 뷰

- [ ] 월요일부터 일요일까지 7일이 표시된다.
- [ ] 날짜 카드를 클릭하면 선택 날짜가 바뀐다.
- [ ] 이전 주 / 다음 주로 이동할 수 있다.
- [ ] 날짜별 Todo 개수가 표시된다.
- [ ] 오늘 날짜가 시각적으로 구분된다.
- [ ] 새로고침 후에도 선택한 주차가 유지된다.

### localStorage

- [ ] Todo 추가 후 새로고침해도 데이터가 유지된다.
- [ ] Todo 수정 후 새로고침해도 변경 내용이 유지된다.
- [ ] Todo 완료 상태가 새로고침 후에도 유지된다.
- [ ] Todo 삭제 후 새로고침해도 삭제 상태가 유지된다.
- [ ] localStorage에 JSON 형태로 저장된다.

### 코드 품질

- [ ] 컴포넌트 책임이 명확히 분리되어 있다.
- [ ] 하위 컴포넌트가 localStorage에 직접 접근하지 않는다.
- [ ] Repository는 저장소 입출력만 담당한다.
- [ ] Service는 Todo 도메인 규칙과 순수 데이터 변환만 담당한다.
- [ ] App은 상태 소유와 액션 조립에 집중한다.
- [ ] 날짜 계산 로직이 컴포넌트 안에 흩어져 있지 않다.
- [ ] Todo 데이터 변환 로직이 반복되지 않는다.
- [ ] 불필요한 `console.log`가 없다.
- [ ] 미사용 코드와 주석 처리된 코드가 없다.

## 10. 구현 시 주의할 점

- React에서는 직접 DOM을 찾거나 조작하지 않는다.
- `map()` 렌더링 시 `todo.id`를 `key`로 사용한다.
- 이벤트 핸들러에서 함수를 즉시 실행하지 않는다.
- `localStorage` 초기값 로드는 Repository를 주입받은 커스텀 Hook 내부에서 한 번만 수행한다.
- Repository가 Todo CRUD 비즈니스 규칙까지 담당하지 않도록 주의한다.
- Service는 React Hook을 호출하거나 localStorage에 직접 접근하지 않는다.
- 날짜 문자열은 `new Date('YYYY-MM-DD')`로 직접 파싱하지 않고 로컬 타임존 기준 유틸을 사용한다.
- Todo 수정 중 빈 값을 저장하려 할 때는 기존 값 유지 또는 안내 메시지 표시 중 하나로 일관되게 처리한다.
- 주간 뷰의 "오늘 날짜"와 "선택 날짜"는 서로 다른 개념이므로 스타일도 구분한다.
