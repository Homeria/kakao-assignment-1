# Next.js로 Todo 앱 만들기

## 한 줄 소개

React(Vite) 기반의 2차 Todo 앱을 Next.js App Router와 FastAPI 기반의 풀스택 Todo 앱으로 전환하는 과제입니다.

## 최종 프로젝트

https://github.com/elice-ai-training/kakaotech.campus_assignment3

## 과제 목표

- React(Vite) 기반 Todo 앱을 Next.js App Router 구조로 다시 구성하기
- `page.tsx`, `layout.tsx`, `route.ts` 등 파일 기반 라우팅 방식 이해하기
- Server Component와 Client Component의 차이를 이해하고 역할에 맞게 구분하기
- FastAPI로 Todo CRUD API를 직접 구현하기
- Next.js API Route를 통해 FastAPI 백엔드와 연동하는 흐름 경험하기
- localStorage 기반 상태 관리에서 서버 API 기반 데이터 흐름으로 전환하기
- 환경변수로 API URL, DB URL 등 환경별 설정값을 분리하기
- AI를 단순 코드 생성 도구가 아니라 구현 보조 및 검증 도구로 활용하기

### 3. FastAPI로 Todo CRUD API 구현하기

FastAPI에서 Todo 데이터 모델, DB 설정, Pydantic 스키마, CRUD 엔드포인트를 구현한다.

필수 API:

| Method | URL | 설명 |
| --- | --- | --- |
| GET | `/todos` | Todo 목록 조회 |
| POST | `/todos` | 새 Todo 생성 |
| PUT | `/todos/{id}` | Todo 수정 |
| DELETE | `/todos/{id}` | Todo 삭제 |

2차 과제의 날짜 기반 Todo 기능을 유지하기 위해 Todo에는 날짜 필드를 포함한다.

권장 Todo 필드:

- `id`
- `title`
- `completed`
- `date`
- `created_at`
- `updated_at`

- Todo 삭제 후 목록에서 제거되는가?

### 5. API Route 작성하고 프론트-백엔드 연동하기

Next.js API Route는 클라이언트와 FastAPI 사이의 프록시 역할을 한다.

필수 API Route:

- `app/api/todos/route.ts`
- `app/api/todos/[todoId]/route.ts`

요청 흐름:

```text
Client Component
  -> /api/todos
  -> Next.js route.ts
  -> FastAPI /todos
  -> SQLite
```

Server Action 또는 서버 함수 흐름:

```text
Server Component
  -> app/actions.ts
  -> FastAPI /todos
  -> SQLite
```

확인 포인트:

- 클라이언트에서 생성, 수정, 삭제 요청이 `route.ts`를 거쳐 FastAPI로 전달되는가?
- 목록 조회 또는 상세 조회가 서버에서 안정적으로 처리되는가?
- 요청 실패 시 사용자에게 적절한 오류 상태가 표시되는가?

## 도전 미션

### 1. 서버 기반 상태별 필터링 구현하기

- 전체 / 진행 중 / 완료 필터 탭을 구현한다.
- 필터 상태는 `?filter=active`, `?filter=completed` 형태의 URL 파라미터로 관리한다.
- 새로고침하거나 URL을 공유해도 필터 상태가 유지되어야 한다.
- 필터링은 클라이언트 배열 필터링이 아니라 FastAPI 서버에서 처리한다.

API 예시:

| Method | URL | 설명 |
| --- | --- | --- |
| GET | `/todos?filter=active` | 진행 중 Todo 조회 |
| GET | `/todos?filter=completed` | 완료 Todo 조회 |

확인 포인트:

- 필터 탭 클릭 시 URL이 변경되는가?
- URL 직접 입력 시 해당 필터가 적용되는가?
- 브라우저 네트워크 탭에서 필터 쿼리가 서버로 전달되는가?

### 2. 서버 기반 Todo 검색 기능 구현하기

- Todo 내용을 검색할 수 있는 검색창을 구현한다.
- 검색어는 `?search=키워드` 형태의 URL 파라미터로 관리한다.
- 필터와 검색을 동시에 적용할 수 있어야 한다.
- 검색은 FastAPI 서버에서 처리한다.
- 검색어 입력 시 과도한 요청을 막기 위해 디바운스를 적용한다.

API 예시:

| Method | URL | 설명 |
| --- | --- | --- |
| GET | `/todos?search=키워드` | 키워드로 Todo 검색 |
| GET | `/todos?filter=active&search=키워드` | 필터와 검색 동시 적용 |

확인 포인트:

- 검색어 입력 시 URL이 변경되는가?
- 검색 결과가 서버에서 필터링되어 반환되는가?
- 필터와 검색을 함께 사용해도 두 조건이 모두 적용되는가?
- 검색어를 비우면 전체 목록으로 돌아오는가?

## 2차 과제 기능 승계 기준

이번 과제는 단순 샘플 구현이 아니라 2차 결과물을 기반으로 3차 결과물을 만드는 작업이다.

유지할 기능:

- Todo 생성, 조회, 수정, 삭제
- 완료 상태 토글
- 빈 입력값 방어
- 빈 상태 화면
- 날짜별 Todo 분리
- 선택 날짜 표시
- 이전 날짜 / 다음 날짜 이동
- 주간 날짜 선택 UI
- 날짜별 Todo 개수 표시
- 전체 / 진행 중 / 완료 필터

변경할 부분:

- localStorage 저장을 SQLite + FastAPI 저장으로 전환한다.
- `useState` 중심 필터 상태를 URL 쿼리 파라미터 기반 상태로 전환한다.
- 클라이언트 배열 필터링을 서버 쿼리 기반 필터링으로 전환한다.
- React Router가 아닌 Next.js 파일 기반 라우팅을 사용한다.
- 모든 컴포넌트를 Client Component로 만들지 않고, 필요한 부분만 Client Component로 분리한다.

## 자주 발생할 수 있는 에러

### CORS 에러

클라이언트에서 FastAPI로 직접 요청하거나 CORS 설정이 없을 때 발생할 수 있다.

해결 방향:

- 가능한 클라이언트 요청은 Next.js API Route를 거치게 한다.
- FastAPI에는 개발 환경 origin을 허용하는 CORS 설정을 추가한다.

### 환경변수가 undefined인 경우

해결 방향:

- 클라이언트 컴포넌트에서 사용하는 값인지, 서버에서만 사용하는 값인지 구분한다.
- 클라이언트에서 필요한 값은 `NEXT_PUBLIC_` 접두사를 사용한다.
- `.env.local` 수정 후 개발 서버를 재시작한다.

### Server Component에서 이벤트 핸들러를 사용하는 경우

`onClick`, `onChange`, `useState`, `useEffect` 등이 필요한 컴포넌트에는 `"use client"`를 선언한다.

### `useSearchParams()` Suspense 에러

`useSearchParams()`를 사용하는 Client Component는 `Suspense` 경계 안에서 사용한다.

### DB 테이블이 생성되지 않는 경우

`Base.metadata.create_all(bind=engine)`가 실행되는지 확인한다.
